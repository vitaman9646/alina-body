## КОМПАКТНЫЕ МАТРИЦЫ — переход 81→N (2026-10-23, решение владельца)

Лид-магнитов будет много → на каждый больше НЕ нужен 81 пост. Теперь:
- **Алина: 5 постов на лид-магнит** (5 углов: по шагам / страхи-возражения / миф / вместо дорогого / непопулярное мнение).
- **Виталий: 2 поста на неделю тренировки** (по шагам + миф) + анонс новой недели (`scripts/post_announce.py`: текст без ссылки + ссылка на хаб первым реплаем).

Сделано:
- Скилл `warmup-matrix` переписан под компактный формат (ячейки `### 1..N`, без запасных хуков и Discovery). Для Виталия — голос/ссылка/папка переопределяются (t.me/podslishanovkachke, threads-matrix-vitaliy).
- `post_matrix.py`: парсер + порядок ячеек 1→N (было 9 углов × 9 регистров a-i). Вращение по магнитам (fewest-posted first) не тронуто.
- **Миграция `scripts/migrate_matrix_compact.py`**: 13 Алининых матриц 81→5 + 1 Виталия 81→2. posted.json теперь `posted` (ячейки 1..N) + `legacy_posted` (старые 1a/3a — для thread_map ответов и вовлечённости, НЕ перепостятся).
- Старые 81-ячейные версии перезаписаны намеренно (каталог `content/` в .gitignore, в git их не было — восстановление не требуется, по решению владельца о 5 постах).

Усовершенствования (план 2026-10-23, пункты 1 и 3):
- **Журнал кредитов** `content/kie_credit_log.jsonl`: `illib.py` пишет cost (баланс до/после) + модель + label (slug магнита) на каждую генерацию. `build_magnet.py` передаёт slug. Цена магнита = сумма записей по slug.
- **Журнал вовлечённости** `content/engagement.json`: `reply_comments.py` пишет thread_id → {count (чужих комментариев), cell, title, profile, updated}. Через 2-3 недели — первый реальный сигнал, какие посты/углы цепляют.

На заметку: с 5 постами на магнит и 4-8 постов/день новый магнит уходит за ~1 день — если хочешь растянуть, режем частоту крона (не менял).
